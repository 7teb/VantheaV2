# Sidebar, title bar panels and chat archive

## Sidebar

The top left shows the VantheaX wordmark over a slowly drifting purple glow with a fine pixel grid. At the sidebar's right edge sit the bell, a magnifier for Search (Ctrl+K) and the sidebar button; they slide left with the edge when the sidebar closes. Below come New chat (Ctrl+N), Scheduled tasks ("Geplante Aufgaben", the page of scheduled tasks, see scheduled.md; three purple dots while a task runs, a yellow dot while a run waits for an approval) and the sections Pinned, Projects and No project. The chat of a scheduled task carries a small calendar-clock mark before its title. Section labels are small semibold gray words in sentence case, the same as the group labels App and Integrations in the Settings rail. Project names are white with a gray folder icon. The chats of an open project hang off a thin vertical line under the folder icon, their titles a step dimmer than the project name and their age in gray; a little space separates one project from the next. The "+" next to Projects is always visible and offers "Add existing folder" and "Create a project"; Ctrl+O also opens a project folder. "Create a project" opens a dialog ("Create project" / "Projekt erstellen") with a project name and an optional folder: a folder can be dropped onto the field ("Drop a folder here or" / "Ordner hier ablegen oder"), and "Add folder" opens the folder picker, which can also make a new folder. With a folder, the project uses it under the typed name. Without one, VantheaX creates DocumentsVantheaX<name> (characters Windows does not allow in folder names become spaces, a taken name gets " 2", " 3" and so on) and runs git init in it when Git is installed; that local repository has no remote, and a failed git init does not stop the project from being created. The bell ("Activity" / "Aktivität") gets a small purple dot at its top left while a chat waits for you or has a new response. Clicking it switches the sidebar to the activity view: "Priority" ("Priorität") lists the chats that wait for you, then those with a new response, then those still running ("Nothing needs attention" / "Nichts braucht Aufmerksamkeit" when there are none, "Mark all as read" / "Alle als gelesen markieren" while something is unread), and below it all other chats follow newest first without project folders, grouped by Today, Yesterday, the weekdays of this week and Older ("Heute", "Gestern", "Älter"). Rows in this view have a second line with their project's name as the sidebar shows it. "Mark all as read" clears the new-response and question marks; approvals that still wait stay. The bell stays highlighted while the view is on, and clicking it again ("Back to projects" / "Zurück zu den Projekten") shows the project lists again; with the sidebar closed, the bell opens it in the activity view. Each chat row shows on the right, instead of its age: three purple dots while its turn runs, a yellow dot while it waits for you (an approval card, or questions asked while you were in another chat), and a purple dot when a turn finished while you were in another chat ("New response" / "Neue Antwort"). Opening the chat clears the purple dot and the question dot; these dots are not saved, so after a restart every chat shows its age again. A collapsed project shows on its row the most urgent mark of its chats: the yellow dot first, then the purple dot, then the three dots. Like a chat's age, the mark hides while the pointer is on the row. When the order of the chats changes, the rows slide to their new places, and an age or mark that changes crossfades. At the bottom, below a thin line, sit the Settings gear (icon only, its name shows as a tooltip) and, while chats are archived, an archive button with their count. Search lists each matching chat with its title and a second line: the matching part of its text, or, when the title or the project folder matched, the project's name with the full path as tooltip.

## Titlebar

The chat's title sits in the middle; while Settings is open it reads "Settings" ("Einstellungen"). The branch is not in the title bar; it sits in the composer strip (see Composer strip in composer.md).

The X at the top right (and closing the window from the taskbar) only hides the window: VantheaX keeps running in the system tray, so running turns, agents, workflows, background tasks and Phone access go on. Clicking the tray icon shows the window again, and so does starting VantheaX a second time. Right-clicking it opens a menu with "Open VantheaX" ("VantheaX öffnen") and "Quit VantheaX" ("VantheaX beenden"); only Quit ends the app. Signing out of or shutting down Windows also ends it.

From left to right on the right side: the panel buttons Terminal, Browser and Files (Dateien), then Phone access (a phone icon, "Phone access" / "Handyzugriff", see Phone access in phone.md), then the More menu ("More" / "Mehr", three dots), then the window controls. Each panel button opens or closes its panel, and the button of the open panel is highlighted; while Settings is open, a panel button closes Settings and opens its panel. In a window wider than 860 px an opening panel takes its full width at once and its content slides in from the right. A yellow dot on the More button means a sub-agent of this chat waits for approval.

- Terminal: PowerShell terminals of the current chat. Each chat has its own terminal tabs ("New terminal" / "Neues Terminal" adds one). Opening the panel starts a terminal for the current chat when it has none. Switching to another chat while the panel is open starts nothing: a chat without a terminal shows a "New terminal" ("Neues Terminal") button, and only a click on it or on the + starts one. Terminals start in the chat's project folder (in its worktree for a worktree chat, see Worktrees in worktrees.md), or in its workspace folder for a chat without a project; a new chat without a project starts in the home folder. Switching chats shows that chat's terminals and keeps the others running in the background. Terminals opened on the new-chat screen move into the chat that its first message creates. Deleting a chat closes its terminals; quitting the app closes all of them. The agent's own commands (run_command, run_bash) run separately and never use this panel.
- Browser: the in-app browser the agent can drive. Besides web addresses it opens local .html, .htm, .xhtml and .svg files by their absolute path (C:\path\page.html or file:///C:/path/page.html), typed into the address bar or given to the agent, without a local server; the address bar then shows the path and the tab the file name. Other local files, secret files and network paths do not open, and a web page cannot open a local file. A local page loads images, styles, scripts, fonts, media and frames only from its own folder and the folders below it, never a secret file, and it cannot read any local file with fetch or XMLHttpRequest, so a page needs its data inline or next to it as a script. Tabs belong to one chat: the agent of a chat lists, opens, drives and closes only that chat's tabs, and other chats cannot see them. The agent browses in the background, so the panel does not open and focus does not move while it works; opening the Browser panel shows the current chat's tabs live, including the ones the agent drives, and you can click and type in them. Closing the panel or switching chats does not stop or reload any page; a chat keeps its tabs until you close them or delete the chat, and quitting closes all of them. Tabs opened on the new-chat screen move to the chat created from it and keep their logins. Every chat has its own browser profile: logins, cookies and site data stay in that chat, other chats never see them, nothing is written to disk, and the profile is cleared when the chat's last tab closes, when the chat is deleted and when the app quits. A tab the agent drives in the background renders at 1280 by 800; while it is shown in the panel it takes the panel's size and goes back to 1280 by 800 when the panel closes or shows another tab. Page dialogs are answered by the app: alert is dismissed, confirm and prompt are cancelled, also while the tab is shown in the panel, and the agent's next browser result names each dialog with its text. When a page asks before you leave it, a background tab leaves without asking; a tab shown in the panel asks you whether to leave or stay.
  The agent reads a tab's console with browser_console (console messages, uncaught exceptions and failed requests of the current page; numbered entries, after=<last_seq> returns only newer ones; the log restarts on navigation and keeps the newest 1000 entries) and inspects page state with browser_eval, which runs only side-effect-free JavaScript (V8 refuses anything that could change the page) with a 10 second limit. When the page's own script context refuses an expression only because a DOM method is not marked side-effect-free in this Chromium (document.getElementById), the expression runs once more in an isolated script context of the same page; the result says so, and variables of page scripts are not visible there. Both work in plan mode and need no approval.
- Files (Dateien): the folder of the current chat. That is its project folder (the same folder in its worktree for a worktree chat), or for a chat without a project its own workspace folder; a new chat without a project shows "Open a project to browse its files" ("Öffne ein Projekt, um seine Dateien zu sehen"). On the left, a file tree loads each folder when it is opened. Folders are white and files a step dimmer, and thin vertical lines mark the levels of indentation. It hides the same folders as list_files (.git, node_modules, dist, build, bin, obj, target and similar), and a folder with more than 2000 entries shows the first 2000 plus "N more not shown" ("N weitere nicht angezeigt"). The field "Filter files" ("Dateien filtern") lists files whose name contains the text, at most 300, including files inside folders such as .ssh, which the tree also shows. On the right, a read-only viewer has a tab per open file, line numbers, syntax highlighting up to 200,000 characters, the file's path, line count and size, "Copy path" ("Pfad kopieren") and "Show in Explorer" ("Im Explorer zeigen"). A file over 1 MB shows its first 1 MB with a note, and a binary file shows a note instead of content. Secret files such as .env are listed and shown like any other file: the panel is for the user and sends nothing to a model except what Write message and the pull request composer send (see Commit, Push and Create PR below), and that never holds the content of a secret file. While the panel is open it watches the folder and updates the tree and open files when files change on disk. The header buttons hide or show the tree ("Hide file tree" / "Dateibaum ausblenden", only while a file is open), widen the panel to its maximum width ("Expand panel" / "Panel vergrößern", again to "Restore panel width" / "Panelbreite zurücksetzen") and close it. Each chat keeps its own Files panel state: open file tabs, expanded folders and the filter, and in a repository the chosen Files, Changes or History view and each file's File or Changes mode. The chosen Diff view, its range, turn and file are kept per chat as well. Switching chats shows that chat's state and refreshes it from disk, and a chat created from the new-chat screen keeps what was opened there. Git view: in a Git repository (also when the folder is a subfolder of one) the panel shows the folder's Git state, read with git.exe and never sent to a model unless Write message or the pull request composer asks for it. Changed files in the tree and in the filter results show a letter in the status color at the right end of the row (M modified, A added, D deleted, R renamed, C copied, T type changed, U untracked, ! conflict, S submodule) and their name in the same color; hovering the letter names the status, for example "Modified, staged" ("Geändert, gestaged") or "Conflict: both modified" ("Konflikt: beide geändert"). A folder with changes inside shows a half-transparent dot in the color of its strongest change (a deleted file marks its parent folder), ignored entries are dimmed, and a folder that is its own repository shows a folder icon with a Git node ("Own repository" / "Eigenes Repository"). A card between the header and the tree shows the branch row: the branch, then "local only" ("nur lokal") without an upstream in a repository that has a remote, "origin/x no longer exists" ("origin/x gibt es nicht mehr"), "no commits yet" ("noch keine Commits") or a commit hash with "detached" ("losgelöst"), except during a rebase, where it names the branch being rebased; with an upstream, arrows with the commits only local and new on the upstream as of the last fetch and the fetch time ("5m ago" / "vor 5 Min.", or "not fetched yet" / "noch nicht abgerufen"; after a fetch that found no network "offline" and "as of 12m ago" / "Stand vor 12 Min."; while a turn, a sub-agent or a background task works in the same repository, the time's tooltip says "Fetch paused while the agent works" / "Abruf pausiert, solange der Agent arbeitet", and after Refresh in that time "Fetch paused while the agent works, it runs right after" / "Abruf pausiert, solange der Agent arbeitet, er läuft direkt danach"); then "N stash entries" ("N Stash-Einträge"). The fetch time is the newer of the app's own last fetch and the repository's FETCH_HEAD for that remote. Hovering the branch names the upstream and remote, the subfolder, the superproject or the main worktree. A slow status read shows "Reading status" ("Status wird gelesen") in place of the time. A running merge, rebase, git am, cherry-pick, revert or bisect adds a row with an hourglass, the step ("Step 2 of 5" / "Schritt 2 von 5") and the conflict count, and failed watchers add "Changes are not detected automatically" ("Änderungen werden nicht automatisch erkannt"). In a repository the header title becomes a switch "Files" ("Dateien") / "Changes" ("Änderungen") / "History" ("Verlauf") with the number of changed files after Changes; once the chat has a turn the switch also has "Diff" (see Diff view below), and in a folder without Git the title is then a switch "Files" / "Diff"; Changes is greyed out while nothing is changed, and when its list empties while it is shown (for example after a commit) the panel goes back to Files. Changes shows the changed files inside the shown folder (for a subfolder of a repository only those under it) in place of the tree, sorted by path in the groups "Conflicts" ("Konflikte"), "Changed" ("Geändert", M A D R C T) and "Untracked" ("Nicht versioniert"), with group labels only when at least two groups have entries. Each row has the status letter, the name (struck through when deleted), its folder or "← old name" for a rename, and on the right the added and removed lines against the last commit ("+3 -2", from git diff --numstat; "binary" / "binär" for binary files, nothing for untracked files and conflicts). Clicking a modified, renamed, copied, type-changed or deleted file opens it in the viewer in Changes mode, an added, untracked or conflicted file in File; untracked folders, nested repositories and submodules are rows without an action. For a modified, renamed, copied or type-changed file the viewer's tab bar has a switch "File" ("Datei") / "Changes" ("Änderungen"): File shows the text with bars next to the line numbers (green added, yellow changed, a red mark where lines were deleted), Changes shows the hunks against the last commit with 3 lines of context and line numbers, without syntax colors, and the path line then shows "+N -N" instead of lines and size. Opening from the tree uses File, opening from Changes uses Changes where the file has the switch. A deleted file opens straight in its diff (a file removed from Git but still on disk, as after git rm --cached, has the switch), an added file in File with its bar; untracked files and repositories without commits have only File. Notes below the path line: "Git treats the file as binary, no line diff" ("Git behandelt die Datei als binär, kein Zeilendiff"), "Only line endings changed, no content difference" ("Nur Zeilenenden geändert, kein Inhaltsunterschied"), "Content not available locally (partial clone)" ("Inhalt nicht lokal vorhanden (Partial Clone)"), "No content changes" ("Keine Inhaltsänderung"), and for a conflicted file its kind, for example "Conflict: both modified" ("Konflikt: beide geändert"), with the conflict marker lines in orange and no switch. When Git fails on a diff, the viewer shows "The changes could not be read" ("Die Änderungen konnten nicht gelesen werden"). In Changes the header button for the left column reads "Hide list" / "Show list" ("Liste ausblenden" / "Liste einblenden"). History is greyed out in a repository without commits; when its repository has no commits any more, the panel goes back to Files. History uses the full panel width, has no left-column button and shows at the top a commit graph of all local branches, remote branches, tags and HEAD (no stash commits), for the whole repository also when the folder is a subfolder of it. Each commit is one row: colored lanes, a ring for a commit, a ring with a dot for a merge and a filled dot for HEAD, up to two labels (the current branch with a ring, then its upstream, other local branches filled, remote branches outlined, tags with a tag icon; the rest as "+N" with the names in its tooltip; a branch checked out in another worktree names that folder in its tooltip), the subject, the author (hidden below 420 px) and the time since the commit. The graph loads 200 commits at a time as you scroll down and is read again, as deep as it was loaded, when a branch, tag, remote branch or HEAD changes; a shallow clone ends with "History ends here (shallow clone)" ("Verlauf endet hier (Shallow Clone)"). Below the graph are the details of the chosen commit, HEAD until you click another row; each chat remembers its chosen commit and how far the graph was scrolled. They show the subject, the author with the e-mail address in its tooltip, date and time, the short hash with "Copy hash" ("Hash kopieren"), the parent ("Parent 4276a37" / "Elternteil 4276a37", for a merge "Merge, diff against first parent 4276a37" / "Merge, Diff gegen ersten Elternteil 4276a37"), the message with the line breaks inside a paragraph joined (list items, lines starting with # and indented lines keep theirs; copying the whole message copies the original text), and "Files" ("Dateien") with each changed file's status letter, name, folder or old name and line counts (in a partial clone whose contents are not local, without line counts and with a rename shown as a deletion and an addition). Clicking a file opens its diff against the first parent right below it, one file at a time, with the same notes as the viewer for binary files and missing content. When Git fails, the list shows "The history could not be read" ("Der Verlauf konnte nicht gelesen werden") and the details "The commit could not be read" ("Der Commit konnte nicht gelesen werden"). Below 420 px panel width the panel shows one column at a time: opening a file or change hides the tree or list so the viewer gets the full width, the left-column button brings the tree or list back over the full width, and both switches show only their icons. Instead of the branch row the card shows one notice: "Git is not installed" ("Git ist nicht installiert", only for folders inside a repository) or "Git 2.30.1 is too old" ("Git 2.30.1 ist zu alt"; the view needs 2.33, partial clones 2.45), both with "Download Git for Windows" ("Git for Windows laden"); "Repository belongs to another user" ("Repository gehört einem anderen Benutzer") with the git config --global --add safe.directory command to copy, which the app never runs itself; "Folder is not tracked" ("Ordner ist nicht versioniert", with "In the repository <folder>" / "Im Repository <folder>" below it) for a project folder that is untracked or ignored in a parent repository (chat workspace folders show nothing); "Git reported an error" ("Git meldet einen Fehler") with Git's first error line, or ".git points to a missing folder" (".git verweist auf einen fehlenden Ordner"). A folder without a repository shows no Git part. "Refresh" ("Aktualisieren") in the header, shown whenever a Git part is, reads the Git state, the shown folders and the open files again and fetches (its icon turns and its tooltip says "Fetch running" / "Abruf läuft" while a fetch runs; Refresh during a running fetch ends it and starts it again); installing or updating Git is also picked up on the next window focus (a Git installed outside the standard folders, found only through the registry, on Refresh or when the panel opens). Background fetch: while the panel shows a repository, the app runs git fetch for its primary remote only (the remote of the branch's upstream, else origin, else the only remote), by name, without FETCH_HEAD, submodules or maintenance, and with prompts off, so missing credentials fail instead of opening a dialog. It fetches when a repository is shown for the first time since the app started, every 3 minutes while the panel is open and the window has focus, on window focus when the last fetch is older than 3 minutes, and on Refresh. It never runs while a turn, a sub-agent or a background task of any chat works in a folder of the same repository (also another worktree of it); Refresh then fetches right after they end, other triggers wait for the next one. A fetch keeps running when the chat or panel changes and ends when the app quits. Never fetched, also not on Refresh: remotes over http://, git:// or ftp://, also behind a remote helper (http::http://...), repositories whose own configuration sets a program the fetch would start (core.sshCommand, core.alternateRefsCommand, credential helpers, core.gitProxy, protocol.*.allow, remote.*.uploadpack or receivepack), and remotes whose fetch refspec writes outside refs/remotes and refs/tags or that are mirrors. The card then shows "Automatic fetch off" ("Automatischer Abruf aus") with "Unencrypted connection" ("Unverschlüsselte Verbindung"), "Repository configuration starts programs (core.sshCommand)" ("Repository-Konfiguration startet Programme (core.sshCommand)") or "Fetching would move local branches (remote.origin.fetch)" ("Abruf würde lokale Branches umsetzen (remote.origin.fetch)"); the user fetches there themselves and the panel picks up the result. Fetch problems add a row: "Git has no credentials for github.com" ("Git hat keine Zugangsdaten für github.com") with git fetch origin to copy (tooltip "Run this once in a terminal, then Git remembers the sign-in." / "Einmal im Terminal ausführen, danach merkt sich Git die Anmeldung."), "SSH key for github.com rejected" ("SSH-Schlüssel für github.com abgelehnt") or "Host github.com is not confirmed yet" ("Host github.com ist noch nicht bestätigt") with ssh -T git@github.com to copy, "origin not found or no access" ("origin nicht gefunden oder kein Zugriff"), and "Fetch failed" ("Abruf fehlgeschlagen") with the first line Git printed for anything else; a lock held by another Git command shows nothing and the next trigger tries again. The ssh command of the fetch is the user's own (GIT_SSH_COMMAND, core.sshCommand from the system or global config, GIT_SSH, else ssh) with batch mode added (-o BatchMode=yes, -batch for PuTTY plink). An ssh remote whose host is an alias (for example git@github-work:o/r or git@github.com-work:o/r) shows the host name the alias stands for, read with ssh -G from the user's own ssh or Git's bundled one, never with an ssh command from the repository's configuration; the lookup runs in the background once per alias while the panel shows the folder, so the card shows the alias until the answer arrives. Apart from the fetch, which only updates remote-tracking branches and tags, and Commit and Push (see Commit, Push and Create PR below), the panel never writes to the repository, and programs set in the repository's own configuration (hooks, filters, fsmonitor, diff drivers), also in submodules, never run.
  GitHub row: when the primary remote points to github.com (also ssh.github.com, or an ssh alias that resolves to it), to a GHE.com host, or to a GitHub Enterprise Server host the GitHub CLI has an account for, the card ends with a GitHub row; other hosts and local remotes show none (for a remote on another host the app asks gh auth status about that one host only). It is a skeleton while the first answer loads. With data it shows an open lock for a public repository and a lock otherwise, the repository name, and on the right the newest pull request of the current branch ("#15 Open" / "#15 Offen", "Draft" / "Entwurf", "Merged" / "Zusammengeführt", "Closed" / "Geschlossen", also one opened from a fork into its parent) and the checks of its head commit, read from the repository the pull request is in, else of the branch on GitHub ("3 passed" / "3 bestanden", "1 failed" / "1 fehlgeschlagen", "1 running" / "1 läuft", "Action required" / "Aktion nötig", "2 skipped" / "2 übersprungen"); with a detached HEAD (also during a rebase) only the repository. When the branch changes, its pull request and checks disappear at once until the next update brings the new branch's. Clicking the row opens the details: the name with "Public" ("Öffentlich"), "Private" ("Privat") or "Internal" ("Intern"), "Archived" ("Archiviert") and "Fork of x/y" ("Fork von x/y"), after a rename "Remote URL still uses <old name>" ("Remote-URL nutzt noch <alter Name>"); "Branch on GitHub" ("Branch auf GitHub"), comparing GitHub's head with the remote-tracking branch and the local commits: "same as local" ("gleich wie lokal"), "differs from local" ("anders als lokal", for a branch without an upstream whose HEAD is not GitHub's head), "4 local commits missing" ("4 lokale Commits fehlen"), "3 new commits, not fetched yet" ("3 neue Commits, noch nicht abgerufen", with "; 2 local missing" / "; 2 lokale fehlen"), "rewritten" ("umgeschrieben"), "not pushed yet" ("noch nicht gepusht"), or "not fetched yet" ("noch nicht abgerufen") without a remote-tracking branch; "Open on GitHub" ("Auf GitHub öffnen"); the pull request with its title and, while it is open or a draft, review counts ("1 approved, 1 changes requested, 1 pending" / "1 freigegeben, 1 Änderungen angefragt, 1 ausstehend"; counts, not GitHub's merge decision); "CHECKS" with the workflow runs, the check runs of other apps and the commit statuses, each with its duration ("41 s", "1 min 12 s" / "1 Min. 12 s"), linked when the link points to the repository's GitHub host, and "GitHub returns the newest 1000" ("GitHub liefert die neuesten 1000") when GitHub cut the list; at the bottom "via GitHub CLI (@login)" ("über GitHub CLI (@login)") when the data came through gh. With data, the commit details in History get an "Open on GitHub" button. Sources: the signed-in GitHub CLI account for the host first (gh api, read requests only; the app never reads gh's token and has no GitHub sign-in of its own), then for github.com the public REST API without sign-in; GHE.com and Enterprise Server only through gh. Rows without data: the repository name with gh auth login to copy (tooltip "Private repository or not found. After signing in to the GitHub CLI, pull request and checks appear." / "Privates Repository oder nicht gefunden. Nach der Anmeldung in der GitHub CLI erscheinen Pull Request und Checks."), or with "Private repository or not found" ("Privates Repository oder nicht gefunden") and "Download GitHub CLI" ("GitHub CLI laden") when gh is not installed, or "GitHub CLI 2.40.1 is too old" ("GitHub CLI 2.40.1 ist zu alt") and "Download GitHub CLI" when gh has no auth status --json; "<repo> is not visible to @login" ("<repo> ist für @login nicht sichtbar") with gh auth login when the gh account cannot see it; "GitHub sign-in expired" ("GitHub-Anmeldung abgelaufen") with gh auth login when GitHub no longer accepts gh's token; "GitHub CLI not signed in for acme.ghe.com" ("GitHub CLI für acme.ghe.com nicht angemeldet") with gh auth login --hostname acme.ghe.com, or with "Download GitHub CLI" when gh is not installed or too old; "acme requires single sign-on" ("acme verlangt Single Sign-on") with "Start SSO session" ("SSO-Sitzung starten"); "GitHub limit reached" ("GitHub-Limit erreicht") with "Resets at 15:00" ("Zurückgesetzt um 15:00"), and when the limit is the one of the public API, gh auth login to copy (tooltip "Resets at 15:00. After signing in to the GitHub CLI, the limit is higher." / "Zurückgesetzt um 15:00. Nach der Anmeldung in der GitHub CLI ist das Limit höher.") or "Download GitHub CLI" ("GitHub CLI laden") when gh is not installed or too old; "GitHub unreachable" ("GitHub nicht erreichbar") and "GitHub is not responding (502)" ("GitHub antwortet nicht (502)"). After data was shown, those problems keep it with a crossed-out cloud and "as of 14:02" ("Stand 14:02") plus "offline", "limit until 15:00" ("Limit bis 15:00") or "GitHub 502" in the row and the details. Updates run only while the panel shows the repository and the window has focus: about once a minute (the max-age GitHub sends), spread out so anonymous reads stay inside GitHub's 60 requests per hour per IP, at once when the branch, its upstream, its remote-tracking branch or the remote changes and on Refresh, and on window focus when the last update is older than that; reopening the panel or coming back to the folder from another project counts like a window focus, so within that time it shows the last state without asking GitHub; Refresh also reads the gh login again and switches to a new or changed gh account; while a row asks for a step outside the app (gh login, SSO), the next focus updates at once. After a 5xx answer the next try waits 60 s, then twice as long each time until focus or Refresh; after a rate limit nothing is sent until the reset. Answers are cached with ETags in memory only. When GitHub reports a head for the branch that the last fetch did not bring, the background fetch runs at once, once per head. Nothing from the GitHub part goes to a model.
  Commit, Push and Create PR: below the Changes list sits a commit box with a message field ("Commit message" / "Commit-Nachricht") and one button. With an empty field the button reads "Write message" ("Nachricht schreiben"): the catalog's `side.git_text` model writes a message from the changes of the shown folder and the latest commit subjects and puts it into the field to edit. It gets the diff against the last commit and the new files, smallest files first, as much as fits that model's context window (the rest is named with its line counts); secret files such as .env and binary files are only named, never sent. While it writes, the field shows a skeleton and the button "Writing message" ("Nachricht wird geschrieben"); the retry icon in the field ("Write again from the changes" / "Neu aus den Änderungen schreiben") writes again. With text the button reads "Commit 3 files" ("3 Dateien committen") and commits every change inside the shown folder: changed and deleted files, and new files except secret files and nested repositories, which stay out and are named below the button ("Left out: .env" / "Nicht dabei: .env"). A new secret file that is already staged (also with git add -N) stays out as well and stays staged. The number on the button counts only the files the commit takes. For a subfolder of a repository only its files are committed; files staged outside it stay staged. The message is kept as written, and a failed commit leaves the index as it was. The button is disabled with the reason below it while the chat's turn runs ("Turn running" / "Turn läuft"), during a merge, rebase, cherry-pick, revert, git am or bisect ("Finish the running operation first" / "Erst den laufenden Vorgang abschließen") and with conflicts ("Resolve conflicts first" / "Erst die Konflikte lösen"). Errors show below it: "Git does not know your name and email yet" ("Git kennt deinen Namen und deine E-Mail noch nicht") with git config --global user.email "you@example.com" to copy, "Nothing to commit" ("Nichts zu committen"), "Another Git command is running, try again" ("Ein anderer Git-Befehl läuft, versuch es gleich nochmal"), "Commit failed: <Git's line>" ("Commit fehlgeschlagen: ...") or "Writing failed: <error>" ("Schreiben fehlgeschlagen: ..."). Commit and Push run with the same guard as every read: the repository's hooks never run, and a repository with hooks (core.hooksPath, a hook file in its hooks folder or a .husky folder) gets the note "The repository's hooks do not run here" ("Die Hooks des Repositorys laufen hier nicht") in the commit box. When the repository's own configuration sets a filter or a signing program (filter.*, gpg.program), Commit and Push are disabled with "Repository configuration starts programs (filter.lfs), use a terminal" ("Repository-Konfiguration startet Programme (filter.lfs), nutze ein Terminal"); Push also for the programs that turn the background fetch off. Commit, Push and Create PR are refused while a turn, a sub-agent or a background task of any chat works in the same checkout ("An agent works in this folder" / "Ein Agent arbeitet in diesem Ordner"); work in another worktree of the repository does not count. The last row of the Git card holds Push and Create PR when they apply. Push ("Pushing" / "Wird gepusht" while it runs) shows when the branch has commits its upstream lacks, has no upstream in a repository with a remote, or its upstream is gone; its tooltip says "Push 3 commits to origin/feature" ("3 Commits nach origin/feature pushen") or "Push and track origin/feature" ("Pushen und origin/feature verfolgen"). It pushes HEAD to the upstream branch, or with -u to a branch of the same name on the primary remote, never with force, without submodules, with prompts off and the user's own ssh like the fetch; remotes and push URLs over http://, git:// or ftp:// are refused. Push problems add a row under it: "Push rejected: origin has commits you don't have yet" ("Push abgelehnt: origin hat Commits, die dir fehlen"), "origin refused the push" ("origin hat den Push abgelehnt") with the remote's message, the credential and SSH rows of the fetch with git push origin HEAD:feature or git push -u origin HEAD to copy, "github.com is unreachable" ("github.com ist nicht erreichbar") or "Push failed: <Git's line>" ("Push fehlgeschlagen: ..."). Create PR ("PR erstellen") shows when the GitHub row has data, the branch is not the repository's default branch and has no open or draft pull request; pull requests from a fork into its parent are not offered. It opens a pull request composer under the card ("PULL REQUEST into main" / "nach main") whose title and description the `side.git_text` model writes from the branch's commits and its diff against the remote default branch (same rules as the commit message); both can be edited, and the close button or "Cancel" ("Abbrechen") drops them. The foot says "Pushes 3 commits to origin first" ("Pusht vorher 3 Commits nach origin") when the branch is not pushed yet; "Create" ("Erstellen") then pushes and runs gh pr create with the user's GitHub CLI login (--repo, --head, --base, --title, --body, base is always the default branch), closes the composer, and the GitHub row shows the new pull request. Without the GitHub CLI the composer shows "Needs the GitHub CLI" ("Braucht die GitHub CLI") with "Download GitHub CLI", signed out "GitHub CLI not signed in for github.com" with gh auth login to copy. Other results: "No commits to propose" ("Keine Commits für einen Pull Request"), "A pull request for this branch exists already" ("Für diesen Branch gibt es schon einen Pull Request") with "Open on GitHub", or the push row text when the push failed. Write message, Push and Create PR are disabled while the chat's turn runs. Switching the branch clears the commit box and closes the composer.
  Diff view: the fourth view of the switch, "Diff" (tooltip "Changes of this chat's turns" / "Änderungen der Turns dieses Chats"), works also in folders without Git and is greyed out until the chat has a turn. It shows what changed in the chat's folder during a turn. At the start of every turn (not compaction-only turns; tools wait for it, the first model request does not) and when its loop ends, also after Stop or an error, the app takes a snapshot of the folder's working tree with Git, written with its own index and object store in `%APPDATA%\VantheaX\v2\turn-diffs\<chat id>\` that borrow the repository's objects; the repository's branches, refs, HEAD, index, stash and files are never touched, nothing shows in git log or gets pushed, and hooks, filters from every config scope and fsmonitor never run. Ignored files are not part of a snapshot; files marked assume-unchanged or skip-worktree count as unchanged; files with a Git filter attribute (Git LFS, nbstripout and the like) are compared by their bytes on disk, so their full content is stored once per chat; when the repository's Git settings normalize line endings (core.autocrlf, text attributes), a change of only line endings is not shown, the same as in the Changes view; a worktree chat snapshots its own worktree, and after the project folder is renamed or moved the chat's diffs are read from its new place. A turn here is the same unit as the file card: the turn plus its agent report and agent update turns. A background task or sub-agent run that started in the chat's newest turn and ends after that turn's end snapshot, while no newer turn has started, takes the end snapshot again. Above the list a switch "This turn" ("Dieser Turn") / "Whole chat" ("Ganzer Chat") picks the range, followed by the turn's start time, or "since <time>" ("seit <Zeit>") for the whole chat, with the date instead of the time when it is not today and the full date and time in the tooltip. This turn is the turn whose card opened the view, else the newest turn (a running turn included); choosing Diff in the switch, or a newer turn starting, goes back to the newest turn; Whole chat compares the start snapshot of the chat's first turn that has one with a snapshot of the folder now. Below come the count ("3 files" / "3 Dateien") with the total added and removed lines, the notes, and one row per file sorted by path: the status letter (A added, M modified, D deleted, R renamed, T type changed, S submodule or nested repository), the name (struck through when deleted), its folder or "← old name" for a rename, and on the right the line counts, "binary" ("binär") for binary files, or for a submodule or nested repository its two commits ("a1b2c3d → e4f5a6b", "none" / "keiner" for a missing side); those rows have no action and their contents are not part of the snapshot. Clicking a file shows its diff on the right: the path with "+N -N", "Copy path" and "Show in Explorer" (not for a deleted file), then the hunks with 3 lines of context as in the Changes view; "Binary file, no line diff" ("Binärdatei, kein Zeilen-Diff"), "The snapshot content of this file is no longer available" ("Der Snapshot-Inhalt dieser Datei ist nicht mehr verfügbar", for example after the repository was re-created or gc removed borrowed objects), "Only line endings changed, no content difference" and "No content changes" (a pure rename) replace the hunks where they apply. In a wide panel the first file opens when the list arrives. The list is virtualized and each file's diff loads when it is opened, so there is no cap on files or lines. Notes above the rows: "Turn still running, changes so far as of 14:07" ("Turn läuft noch, Änderungen bis 14:07"); for Whole chat "Compared with the folder as of 14:09" ("Verglichen mit dem Ordner um 14:09"); for a turn whose end snapshot is missing "The app was closed during this turn, compared with the start of the next turn" ("Die App wurde während dieses Turns geschlossen, verglichen mit dem Start des nächsten Turns") or "... compared with the folder as of <time>", and for a failed end snapshot "The end snapshot of this turn failed (<Git's error>), ..." ("Der End-Snapshot dieses Turns ist fehlgeschlagen (...), ..."); "Git could not read 2 files when the snapshot was taken: <every path>" ("Git konnte beim Snapshot 2 Dateien nicht lesen: ...") for files another program held locked; "Git skipped rename detection because of the number of files, renames show as a deletion and an addition" ("Git hat die Erkennung von Umbenennungen wegen der Dateianzahl übersprungen, ..."); and for Whole chat in a chat whose first turns ran before this feature "Turns before <time> ran without a snapshot and are not included" ("Turns vor <Zeit> liefen ohne Snapshot und sind nicht enthalten"). Without Git, that is in a folder that is no repository, with Git missing or older than 2.33, in a repository of another Windows user, in a folder its parent repository ignores, or when the start snapshot failed (a full disk, for example), the app saves the bytes of each file the agent's file tools (also of sub-agents) write, and of the screenshots check_page saves, before the first write in the turn and again at its end, and the first note says so: "Not a Git repository: only files written by the agent's file tools are shown, changes made by commands are not included" ("Kein Git-Repository: angezeigt werden nur Dateien, die die Dateiwerkzeuge des Agenten geschrieben haben, Änderungen durch Befehle sind nicht enthalten"), likewise "Git is not installed", "Git 2.20.1 is too old", "The repository belongs to another user", "The folder is ignored by the repository at <folder>" and "The snapshot failed (<error>)"; files that could not be read then are named in a note. A turn from before this feature shows "No snapshot exists for this turn" ("Für diesen Turn gibt es keinen Snapshot"), Whole chat without any snapshot "No snapshot exists for this chat yet" ("Für diesen Chat gibt es noch keinen Snapshot"), a turn without changes "No files changed in this turn" ("In diesem Turn wurden keine Dateien geändert", for Whole chat "... in this chat"), and a read that fails "The diff could not be read: <error>" ("Der Diff konnte nicht gelesen werden: <Fehler>"). A finished turn's file list never changes on its own; a running turn and Whole chat are compared with the folder again when the view is shown, on Refresh in the header (which in the Diff view reloads the chat's diffs, also outside Git) and when a turn of the chat starts or ends, not on every file change, which is why the note names the time. The header button for the left column reads "Hide list" / "Show list", and below 420 px the list and the diff show one at a time as in Changes. Nothing from the Diff view is sent to a model.

More menu:

- "Background tasks" ("Hintergrund-Tasks"): opens the Background Tasks panel of the current chat. It lists the chat's sub-agents and its background shell tasks together, newest first, in two sections with a chevron each: "Running" ("Läuft") and "Ran" ("Beendet"). Collapsing a section is remembered. An agent row shows its topic, profile (and the tools removed from it, if any) and model, a stop button while it runs, and its runs, each with the first line of its task and on the right one value: "Waiting for approval" ("Wartet auf Freigabe") while it waits for an approval, "1 open question" ("1 offene Frage") while it waits for an answer, otherwise its duration; opening a run shows its transcript, its report and a Stop button while it runs, and "Back to background tasks" ("Zurück zu Background Tasks") returns to the list. A shell task shows its status icon, its command and on the right its duration, or "exit 1" ("Exit 1") when it ended with an exit code other than 0, that value in red when the task failed; below that a collapsible output, and a cancel button while it runs. A badge shows how many agent runs and tasks of the chat are running, and a yellow dot on the item means an agent waits for approval. - "Generated images" ("Generierte Bilder"): every image generate_image made in the project, also the ones the agent did not show in the chat, with pin, rename and export.
- "Keep computer awake" ("Computer wach halten"): a toggle that starts Electron's `prevent-app-suspension` power save blocker, which keeps the system from entering a low-power mode. ## Chat archive

Archive ("Archivieren") in a chat's "..." menu in the sidebar archives the chat; it is disabled while the chat's turn runs. The "/" command Archive chat does the same for the open chat. An archived chat leaves the Pinned, project and No project lists of the sidebar and the previous/next chat shortcuts. Archiving the open chat switches to a new chat in the same project. While at least one chat is archived, an archive button with the count sits next to the Settings gear at the bottom of the sidebar (tooltip "Archived" / "Archiviert"). It opens "Archived chats" ("Archivierte Chats"), newest first, each row with the chat's title, its project's name (the full path as tooltip) and its age. Clicking a row opens the chat; an archived chat can be read like any other; any turn that starts in it (a message, Continue, Initialize, Create GitHub repository, Review, an accepted plan, Undo, Compact or a report from one of its agents) restores it to the lists, pin included. "Restore" ("Wiederherstellen") puts the chat back into the lists, pin included, and the trash button deletes it after a confirmation. Search finds archived chats and marks them with an archive icon and an "Archived" ("Archiviert") tag; the Recent list shown before typing leaves them out. A fork of an archived chat is not archived. Chats saved before the archive existed load as not archived. Archiving a worktree chat keeps its worktree folder.

## Selecting text

Buttons, menus, tabs, the title bar, the sidebar, the composer controls (model, effort, mode), panel headers, tooltips and code block headers cannot be selected or copied. Ctrl+A selects only the area it was pressed in: the chat, a code block or command output in the chat that was clicked last, the open file in the Files panel, or the body of an open side panel. Outside these areas (sidebar, composer controls, settings) Ctrl+A selects nothing; in a text field and in the terminal it works as usual.

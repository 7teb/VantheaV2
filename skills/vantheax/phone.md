# Phone access

## Phone access

VantheaX can be used from a phone or tablet in the same local network as the PC, LAN only: no tunnel, no relay, nothing reachable from the internet. The phone icon in the title bar (left of the More menu, only on the PC) opens a popover with a switch ("Phone access on the local network" / "Handyzugriff im lokalen Netzwerk"). It is off at every start of the app and only the owner turns it on at the PC. While it starts, a skeleton stands where the QR code goes. Once on, the icon gets a small green dot and the popover shows a QR code of the pairing link ("Scan with a phone on the same Wi-Fi" / "Mit einem Handy im selben WLAN scannen"), the address of each network interface (with several, a click picks which one the QR code uses), the hint "If Windows asks, allow VantheaX on private networks" ("Wenn Windows fragt, VantheaX in privaten Netzwerken zulassen"), how many devices are connected, and "New link" ("Neuer Link"), which makes a new QR code and unpairs every device at once. A start that fails says why: no local network, no free port, secure storage not available for the pairing key, or the error.

The server listens only on the PC's private IPv4 addresses (10/8, 172.16/12, 192.168/16) from port 47820 upward. Scanning the QR code pairs that browser with an HttpOnly session cookie and the page drops the key from its address right away; the pairing stays across restarts until New link. New link also cuts off requests that were still arriving or running at that moment: they are not carried out, or their result is not sent back. A paired device can do everything the owner can do in the app, commands included. A page that is not paired shows "This device is not paired" with the hint to scan the QR code at the PC.

On the phone the app is the same app with the same design: chats, the message box with model, effort, permission mode (Auto and the rest), "/" commands, attachments, approvals and questions, tool groups, sub-agents, the Background Tasks panel, generated images, the Files panel with Git, turn diffs, the terminal and the settings, fitted to the screen with the chat list behind the sidebar button. PC and phone are clients of the same app, so a message, an approval or a rename on one shows on the other at once. Unsent text in the message box stays on the device it was typed on. A terminal opened on the phone shows only there and closes when that page reloads or the link is renewed. When PC and phone show different folders in the Files panel, the one opened last follows changes on disk.

Hidden on the phone because they need the PC's own window or dialogs: the window buttons and the zoom and fullscreen shortcuts, the Browser panel and its title bar button (the agent's browser tools still run and their screenshots show in the chat), "Add existing folder" and Ctrl+O, the folder choice in "Create a project" (a project created on the phone goes to Documents\VantheaX\<name> on the PC), "Work in a project" in the "+" menu, Show in Explorer in the Files panel and on shown images, "Choose plugin folder" for MCP servers, "Open folder" for skills, Phone access itself, and the microphone button (the http page in the LAN gets no microphone, and iOS records no WebM/Opus; the phone keyboard's own dictation still types into the message box). On the phone, attachments are picked through the browser's file picker (photos, camera or files) and uploaded to the PC, links open in a new tab of the phone's browser, exporting a generated image downloads it, and copy buttons work there too. When the connection to the PC drops, a pill in the title bar says "Connecting to the PC" ("Verbinde mit dem PC") or "No connection to the PC" ("Keine Verbindung zum PC"), and the page catches up on what it missed once the PC is reachable again; after an app restart it reloads, and after a new link it shows the not-paired page.

### Connecting a phone

1. PC and phone are in the same local network: the same router, the phone on that router's normal Wi-Fi (not a guest network). Whether the PC uses Wi-Fi or a cable does not matter.
2. On the PC, click the phone icon in the title bar and switch Phone access on.
3. If Windows asks whether VantheaX may communicate on networks, allow it on private networks.
4. Scan the QR code with the phone's camera and open the link in the browser (Safari or Chrome). The phone is paired and shows the app. "Add to Home Screen" in the browser gives it an icon.

How it works: the main process runs a plain HTTP server on the PC's private IPv4 address (port 47820 or the next free one). It serves the app's own interface, takes the app's commands at POST /rpc and pushes every live update as Server-Sent Events at /events, so phone and PC share one state. The QR link carries a one-time key that the server swaps for a session cookie. The connection inside the LAN is not encrypted.

### When the phone cannot connect

- The page loads forever or times out: Windows drops the connection, almost always because the PC's network is set to Public. Check it without admin rights in PowerShell with `Get-NetConnectionProfile` (NetworkCategory). Fix: Settings → Network & Internet → Wi-Fi (or Ethernet) → the network → Network profile type: Private. As a command this needs a PowerShell started as administrator: `Set-NetConnectionProfile -InterfaceAlias "<alias from Get-NetConnectionProfile>" -NetworkCategory Private`.
- Still blocked on a private network: the Windows question was dismissed or denied, so the firewall has no allow rule for VantheaX. Fix: Windows Security → Firewall & network protection → Allow an app through firewall → tick VantheaX for Private. As a command, again in an administrator PowerShell: `New-NetFirewallRule -DisplayName "VantheaX LAN" -Direction Inbound -Program "<full path of VantheaX.exe>" -Action Allow -Profile Private`. The rule belongs to that exe path; after moving the app folder it needs a new rule.
- The app's shell runs without administrator rights, so an agent cannot change the network profile or the firewall itself; it gives the user the Settings path or the command above to run in an administrator PowerShell.
- To see where it fails, on the PC: `Get-NetTCPConnection -State Listen -LocalPort 47820` shows whether the server listens and on which address, and `Invoke-WebRequest http://<that address>:47820/ -UseBasicParsing` answers 401 (not paired) when the server itself works. While the phone loads the page, `Get-NetTCPConnection -LocalPort 47820` shows a connection from the phone's address if its packets reach the PC; if none shows up, the block is in Windows or the router, not in the app.
- The phone is in another network: its IP address (in the phone's Wi-Fi details) must start like the PC's address shown in the popover, for example both 192.168.178.x. Guest networks, a router setting that isolates Wi-Fi devices from each other, and a VPN on the phone or the PC all stop the connection.
- The PC's address changed (another network, new address from the router): switch Phone access off and on and scan the new QR code. The pairing belongs to the old address, so the phone pairs again.
- "This device is not paired": scan the QR code again. After New link every device has to scan again, and so does a browser whose site data was cleared.

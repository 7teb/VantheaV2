# Settings, data locations and the model catalog

## Settings

Sections: App group with General (Allgemein: Language, the Billing group ("Billing" / "Abrechnung", see Billing, the ChatGPT plan and the Claude plan below) with the GPT models switch, the ChatGPT account, the Claude models switch, the Claude Code login, the OpenRouter API key and Key balance, under Appearance / Darstellung the row "Accent color" / "Akzentfarbe" with eight swatches (Violet / Violett as the default, Blue, Cyan, Green, Amber, Orange, Red, Pink) and a "Custom color" / "Eigene Farbe" swatch that opens the system color picker; the chosen color replaces the violet everywhere it was used (send button, your message bubbles, the effort picker, the context ring and context panel, the animated field behind the VantheaX name at the top left, links, spinners and other highlights), the glyph on the send button turns dark on light colors, and the choice is saved in settings.json as `accent_color` and kept across restarts, and under Notifications / Benachrichtigungen the switch "Notification sound" / "Benachrichtigungston", on by default: while the VantheaX window is not focused, a short soft chime plays when a main-agent turn ends for any reason except the user's Stop, including provider errors, and a slightly brighter one when the main agent asks the user a question or shows an approval card; sub-agents never chime, and chimes closer than two seconds apart play once) , Personalization (Personalisierung: Personality, Custom instructions, Memory) and Privacy (Datenschutz: under "Chats and projects" / "Chats und Projekte", "Archive all chats" archives every chat except those with a running turn, "Delete all chats" deletes every chat including archived ones with their attachments, and "Remove all projects" removes every project and deletes its chats while the folders on disk stay (worktree folders of deleted chats are deleted, their branches stay); each asks for confirmation first and then shows how many it handled); Integrations group (Integrationen) with Web search (Websuche, Tavily API key), Image generation (Bildgenerierung), MCP servers (MCP-Server), Hooks (see hooks.md) and Skills (see skills.md). In the rail on the left the highlight slides to the chosen section, and on a narrow screen a tapped section scrolls into view.

MCP servers has "Add server" ("Server hinzufügen") next to its heading. The add dialog has a label above each field (Name, Command ("Befehl"), Arguments ("Argumente"), Environment ("Umgebung"), "Working folder (optional)" ("Arbeitsordner (optional)")) and example values as placeholders, with the command and the working folder in Consolas. A server's "Tools" section shows only when the server offers tools, and an empty server list shows nothing.

Web search: a search returns the matching sources with the relevant excerpts of their text (Tavily basic search, no second model); results carry their publish date when Tavily knows it, and the agent can ask for news and a time range per search. Reading specific URLs always returns the page text itself to the agent, in windows that fit one tool result with an offset to read on (Tavily basic extraction). URLs that fail are named in the result and shown in red under the sources.

Memory ("Memory (experimental)" / "Erinnerung (experimentell)"): with "Enable memories" ("Erinnerungen aktivieren") on, the main agent gets the remember, forget and list_memories tools and decides itself, in the turn where the user says how they want it to work, corrects it or states a stable fact about their setup, whether that belongs in memory. No other model reads the messages for memories. remember saves one sentence with a kind: global_preference (how the user wants the agent to work) and global_environment (their machine, stack or tools) apply in every project, project_rule only in the chat's project (in a chat without a project, its own workspace folder). Saving or deleting a memory passes the automatic review in Auto and Full and waits for the user in Ask. Saved memories are listed under "Saved memories" ("Gespeicherte Erinnerungen"), where "Remove memory" ("Erinnerung entfernen") deletes one. Memory suggestions from earlier versions that were still waiting for review are listed under "Memory review" ("Erinnerungen prüfen") with Keep ("Behalten") and Discard ("Verwerfen"); at startup the ones at confidence 0.85 or higher that do not match a discarded fact are saved. A group without entries is left out, unless it could not be loaded. The "/" command Memories opens a small panel above the composer ("Memories" / "Erinnerungen") with the saved memories, a trash button per entry and a field to add one; a memory added there is saved directly as a global memory (no review), up to 25000 characters, secrets redacted, and adding the exact same text again keeps a single entry. Escape or the close button closes it. While "Enable memories" is off, the panel notes that saved memories are not used.

The project root may contain AGENTS.md and CLAUDE.md. Every one that is not empty is loaded whole, without a length limit, into the system prompt as project instructions, after the built-in sections and the custom instructions; they take priority over the agent's defaults where they apply. In a worktree chat, a file that is missing in the worktree is read from the same place in the main checkout.

Agents that can write files get code rules in the system prompt: names without g_, m_, s_ or k prefixes, values written where they are used instead of a block of named constants (a constant only when several places share the value or it belongs to a protocol, file format or public interface), the default indentation, and more, plus a separate comment rule: no comments except a one-line reason the code cannot show, and never divider or banner lines, section titles, file headers or commented-out code, in any language. The write_file and replace_in_file descriptions tell the agent to read these rules again before it writes code. In an empty project, or one with no instruction files and no existing code that sets a style, these rules are the whole code style unless the user or the custom instructions set another: the agent follows every one of them, the style rules included, and before it finishes it reads every file it wrote again and checks it rule by rule. Only the user's messages, the custom instructions, the project's AGENTS.md or CLAUDE.md and a convention the project's existing code clearly follows override them; when the user's messages or custom instructions conflict with the style of the existing code, the user wins. After every write_file of a code file, an automatic check looks for newly added names with a g_ prefix and new separator or banner comment lines (a run of ten or more `=`, `-`, `#`, `*`, `~` or `_`). When it finds some, a note is appended to that tool result for the agent: the style is off by default unless the user, the custom instructions, the project's instruction files or its existing code ask for it. The note comes at most twice per chat (each sub-agent counts on its own) and is not shown in the chat view; replace_in_file is not checked.

## Billing, the ChatGPT plan and the Claude plan

The Billing group ("Billing" / "Abrechnung") in Settings > General holds, in this order: "GPT models" ("GPT-Modelle") with the choice "API pricing" ("API-Preise", the default) or "ChatGPT plan" ("ChatGPT-Abo"), the ChatGPT account row, "Claude models" ("Claude-Modelle") with the choice "API pricing" ("API-Preise", the default) or "Claude plan" ("Claude-Abo"), the Claude Code login row, the OpenRouter API key and Key balance. The two switches are independent: either plan can be on alone, and both can be on at the same time, for example the ChatGPT plan for the GPT models and the Claude plan for the Claude models. With either plan on the key row notes "Used for image generation, dictation and models outside your plans" ("Für Bildgenerierung, Diktat und Modelle außerhalb deiner Abos"). The ChatGPT account row is there in both modes of the GPT models switch, so the account and Sign out are always reachable, and the Claude Code login row is there in both modes of the Claude models switch.

Which route a model call takes, for each combination of the two switches ("OpenRouter" means the stored OpenRouter key, exactly as with API pricing, and without a key the usual missing-key error; "Claude models" are Claude Haiku 5.5, Claude Sonnet 5.5, Claude Opus 5.5 and Claude Fable 5.2, the catalog entries with a `claude_code` id):

| GPT models | Claude models | OpenAI models the ChatGPT account offers | Claude models | Every other model |
| --- | --- | --- | --- | --- |
| API pricing | API pricing | OpenRouter | OpenRouter | OpenRouter |
| ChatGPT plan | API pricing | ChatGPT plan | OpenRouter | OpenRouter |
| API pricing | Claude plan | OpenRouter | Claude Code with the Claude plan | OpenRouter |
| ChatGPT plan | Claude plan | ChatGPT plan | Claude Code with the Claude plan | OpenRouter |

Whether a turn runs in Claude Code is decided once when it starts: when the Claude models switch changes in the middle of a turn, a turn on OpenRouter finishes on OpenRouter and a Claude-plan turn finishes in Claude Code. Side jobs (chat titles, status lines, image descriptions, git texts) and the automatic review never run through Claude Code: with GPT models set to ChatGPT plan they use `plan_side` through the ChatGPT plan, otherwise the OpenRouter side models. The live status line always uses the OpenRouter side model, also with the ChatGPT plan or the Claude plan connected.

The ChatGPT account row shows one state at a time. Signed out it shows "Use your ChatGPT plan" ("Nutze dein ChatGPT-Abo") with the text "Complete eligible AI requests in this app with usage included in your ChatGPT plan or credits balance." and the white button "Continue with ChatGPT" with the OpenAI logo before its label, which keeps its English label in the German interface. After an earlier sign-in on this installation it shows that account's email with "Continue with ChatGPT" and "Use another account" ("Anderes Konto verwenden"), which signs in a different account and replaces the remembered one. While the sign-in page is open it shows "Opening ChatGPT..." ("ChatGPT wird geöffnet...") with Cancel ("Abbrechen"). Signed in it shows the account's email or name, "Connected" ("Verbunden"), "Manage usage" ("Nutzung verwalten", opens https://chatgpt.com/settings/usage in the browser) and "Sign out" ("Abmelden"). A sign-in that did not grant plan usage shows "Plan usage is not enabled for this sign-in" ("Die Abo-Nutzung ist für diese Anmeldung nicht aktiviert") with "Enable plan usage" ("Abo-Nutzung aktivieren"), which opens the sign-in again and asks OpenAI for that permission, and Sign out. An expired sign-in shows "Reconnect to ChatGPT" ("Erneut mit ChatGPT verbinden"). The reason of the last failed attempt shows under the row, for example a declined or cancelled sign-in, another account than the remembered one, OpenAI not reachable, or Windows encryption not available.

Signing in opens OpenAI's sign-in page in the system browser. After the sign-in the browser returns to a local address on 127.0.0.1 where only VantheaX listens for that one attempt, and the app stores the sign-in encrypted. Signing in never switches GPT models to ChatGPT plan; that choice is separate. The first time a signed-in account with plan usage meets GPT models set to ChatGPT plan, a dialog with the OpenAI logo above its title "You're using your ChatGPT plan" ("Du nutzt dein ChatGPT-Abo") says that eligible usage in this app uses the ChatGPT plan, with "Got it" ("Verstanden"); it shows once. Sign out revokes the sign-in at OpenAI and deletes the stored tokens; when OpenAI does not confirm the revocation, the row says so, and the app can be disconnected in the ChatGPT settings. Plan usage is OpenAI's sign-in for open-source tools and personal projects that run locally.

With GPT models set to ChatGPT plan:

- The model picker keeps the full catalog, as with API pricing. A model runs on the plan when it is an OpenAI model the signed-in account offers; while the account's model list is not loaded yet, every OpenAI model that routes to OpenAI is tried on the plan and OpenAI's answer decides. For such a model the picker shows the OpenAI logo and "Using ChatGPT plan" at its bottom, and only the speed tiers the account's model list names for it are offered: today Fast, sent as OpenAI's priority tier and counted at about 2 to 2.5 times the plan usage. Pro is locked for such a model: the /pro command stays visible but disabled with the reason "Pro is not part of the ChatGPT plan" ("Pro ist im ChatGPT-Abo nicht enthalten"), a stored Pro choice runs the base model on the plan, and sub-agents and list_models get no -pro id for it, since the plan's model list (the same as in Codex) has no Pro models. Only a Pro slug the account's model list names would run on the plan.
- Every other model (other vendors' models, OpenAI models the account does not offer, and GPT OSS 120B, which does not route to OpenAI) runs through OpenRouter with the stored key, exactly as with API pricing, and without a key shows the usual missing-key error.
- A model on the plan gets the largest context window the account's model list allows for it: `max_context_window`, or `context_window` when that is missing. For GPT 6.2 Sol that is 872k instead of the API's 1.05M, and "Model maximum" under Context limit shows that value.
- Main turns, sub-agents and compaction on a model that runs on the plan count against its usage. The automatic review, chat titles, image descriptions and git texts (commit messages and pull request text) use the plan's side models (`plan_side`, see the model catalog below) through the plan. On Plus the five-hour limit is shared with every other app that uses the plan.
- Dollar costs show only for calls through OpenRouter; list_models marks the models that run on the plan as included in the plan without a price and lists every other model with its OpenRouter price. Token usage is still counted.
- Image generation and dictation are not part of the plan and still need an OpenRouter key; without one they stay unavailable, as with API pricing and no key.
- A call for a model that runs on the plan never moves to OpenRouter on its own, also not when the plan's usage limit is reached; the error is shown instead.
- Chats keep their model when either billing switch changes, and so do scheduled tasks, sub-agents and headless sessions that name a model.
- Each mode of the GPT models switch remembers its own default model: switching back to API pricing restores the model chosen there.

The Claude Code login row ("Claude Code login" / "Claude-Code-Anmeldung") shows the Claude Code login on this computer. VantheaX ships Claude Code (the claude.exe bundled with Anthropic's Claude Agent SDK) and runs Claude-plan turns in it; the user signs in to it with their own Claude subscription through Claude Code's own sign-in. VantheaX never reads, copies or stores Claude credentials and has no Claude sign-in of its own. The row learns the state by running the bundled Claude Code with `auth status --json`: at startup while Claude models is set to Claude plan, when that switch turns to Claude plan, on "Check again" ("Erneut prüfen"), when the row opens while not signed in with the subscription login (state not yet known, not signed in, or signed in another way), and after a Claude-plan turn ended with a login error; it never polls. It shows one state at a time:

- Signed in with the subscription login: the account's email, the subscription type Claude Code reports (for example max) or "Signed in" ("Angemeldet"), and "Check again".
- Not signed in: "Claude Code login" with "Not signed in" ("Nicht angemeldet"), "Check again" and "Sign in" ("Anmelden", with the Claude logo).
- Signed in another way (an API key, a token or a cloud provider instead of the subscription): "Claude Code is set up with another login, the Claude plan needs the subscription login" ("Claude Code ist mit einer anderen Anmeldung eingerichtet, das Claude-Abo braucht die Abo-Anmeldung"), "Check again" and "Sign in".
- Claude Code missing from the installation: "Claude Code is missing from this installation" ("Claude Code fehlt in dieser Installation"), no button.
- State not readable: "The login state could not be read" ("Der Anmeldestatus konnte nicht gelesen werden") with the reason under the row, and "Check again".

"Sign in" opens the terminal panel, which closes the settings page, and types the PowerShell line `& '<path of the bundled claude.exe>' auth login --claudeai` there. That starts Claude Code's own subscription sign-in in the browser; afterwards the user opens Settings again and presses "Check again". The line works the same in any PowerShell window on this computer. Claude Code keeps the login in the user's Claude folder (`%USERPROFILE%\.claude`, or the folder in `CLAUDE_CONFIG_DIR`), the same place an installed Claude Code uses. There is no sign-out button: the login belongs to Claude Code. A turn does not wait for the row; Claude Code's own answer decides.

With Claude models set to Claude plan:

- The model picker keeps the full catalog. The Claude models run on the plan whatever the row shows. For such a model the picker shows at its bottom the Claude logo and "Using Claude plan" ("Claude-Abo aktiv") while the login row is signed in or its state is not known yet, "Not signed in to Claude Code" ("Nicht bei Claude Code angemeldet") while it is not signed in or signed in another way, "Claude Code is missing from this installation" ("Claude Code fehlt in dieser Installation") when Claude Code is missing, and "The login state could not be read" ("Der Anmeldestatus konnte nicht gelesen werden") when the state could not be read, each with "Open settings" ("Einstellungen öffnen"), which opens Settings > General.
- A Claude-plan turn runs in Claude Code with VantheaX's own system prompt, tools, permissions and approval cards (see turns.md). Main turns, sub-agents (see agents.md) and compaction (see context.md) on a Claude model count against the Claude subscription. Side jobs and the automatic review keep the rules above, so with the Claude plan as the only source (no OpenRouter key and GPT models on API pricing) chat titles, status lines, image descriptions, git texts and the automatic review fail with the usual missing-key error.
- Claude-plan turns show no dollar cost; token usage is still counted. list_models marks the Claude models as included in the Claude plan without a price.
- When Claude Code reports that the account would run on extra usage credits beyond the plan, the turn stops at once with the Claude plan limit error, so no credits are spent.
- A Claude-plan call never moves to OpenRouter on its own, also not when the usage limit is reached; the error is shown instead.
- A Claude-plan turn never switches to another Claude model on its own: Claude Code's refusal fallback is off (`CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK=1`), so when the chosen model refuses a request the turn ends with the refusal error instead of an older model answering.
- The Claude models switch does not change the default model; the default model and the remembered one follow the GPT models switch only.
- Image generation and dictation are not part of the Claude plan either.

## Where data lives

Everything is under `%APPDATA%\VantheaX\v2`:

- `settings.json`: settings (language, model, effort, mode, projects, personality, custom instructions, memory, web search, image generation, MCP servers, MCP tool overrides, disabled skills, hooks), plus `billing` (`api` or `chatgpt`, the GPT models switch), `inactive_billing_model` (the default model of the GPT models mode that is not active) and `claude_billing` (`api` or `claude`, the Claude models switch; a settings.json without it loads as `api`).
- `secrets.json`: the OpenRouter and Tavily keys and the Phone access pairing key, encrypted with Electron safeStorage. It also holds the encrypted ChatGPT session: the access, refresh and ID token, the client id OpenAI issued to this installation and the account identity.
- `chatgpt.json`: the installation's host id that the ChatGPT sign-in sends, whether the one-time plan dialog was seen, and the cached model list of the signed-in account. No token is stored here.
- `chats\`: `index.json`, `data\` and `search\`.
- `media\attachments\` and `media\images\`: attached files and generated images; `artifacts.json` lists the artifacts.
- `background.json`: background tasks.
- `scheduled-tasks.json`: scheduled tasks (see scheduled.md); a task's name and project are those of its chat.
- `agents\<agent id>\`: agent context, run journals (`<run id>.jsonl`) and reports (`<run id>.report.md`).
- `memories.json`: the memories, including the ones waiting for review and the last 500 discarded ones.
- `skills\`: user skills and `installed.json`.
- `reads\<chat id>.json`: per agent of the chat, the SHA-256 of every file it last read or wrote, which write_file and replace_in_file compare before they change a file.
- `workspaces\<chat id>\`: working folder of a chat that has no project.
- `worktrees\<id>\<folder>\`: the worktree of a chat that works in its own worktree; `worktrees\ledger.json` records worktree creations and deletions until they finish.
- `turn-diffs\<chat id>\`: the turn diff snapshots of a chat (see Diff view in the Files panel in interface.md): `index` and `objects\`, a Git index and object store with every file version the snapshots saw that the repository does not already have (changed tracked files and untracked files Git does not ignore, `.env` included when it is not ignored); `turns.json` with one record per turn (start and end snapshot, mode, late work); `summaries.json` with cached file lists per pair of snapshots; and in a folder without Git `recorded\<message id>\` with the bytes of the files the agent's file tools wrote, before and after. It is deleted with the chat, a fork gets the parent's snapshots (objects hardlinked), and folders of chats that no longer exist are removed at startup. Nothing in it leaves the machine.

Outside `v2`, every chat gets a scratchpad folder `%TEMP%\VantheaX\scratchpad\<random GUID>` the first time a prompt is built for it in a run of the app. It is for the agent's throwaway files such as test scripts and probes; read_file, get_file_outline, view_image, write_file and replace_in_file accept absolute paths inside it, with the same approvals as files in the project. Each chat only reaches its own scratchpad. The folder is deleted when its chat is deleted or the app closes, and the chat gets a new one in the next run, so nothing that must last belongs there.

Claude Code keeps the sessions of Claude-plan chats and sub-agents in the user's Claude folder (`%USERPROFILE%\.claude\projects\<project folder>\<session id>.jsonl`, or under `CLAUDE_CONFIG_DIR`). VantheaX stores only the session id with the chat file (`claude_session`) or the agent record and deletes the session when the chat or agent is deleted or the session is replaced (see turns.md).

Files directly in `%APPDATA%\VantheaX` (outside `v2`) belong to the previous version; their settings, chats, memories, skills, artifacts and media are imported into `v2`, and the old files are left in place. An older `v2\snapshots\` folder from the previous Undo is deleted once at startup.

## Model catalog

The catalog is the folder `config/models` inside the app (in the packaged app it is part of `resources\app.asar`, so changing it means rebuilding). It is the only place model ids are written down. `index.json` holds `model_files`, `side`, `plan_side`, `side_models` and `image_models`; the agent models live in one file per OpenRouter vendor, named after the prefix of their ids (`openai.json`, `google.json`), each an array of entries. It has five parts:

- `model_files` and the files it names: the agent models. The Model picker lists them in the order of `model_files`, then in file order; a new vendor file loads only once its name is in that list. Each entry has `id` (OpenRouter id), `label`, `provider`, `provider_order`, `efforts`, `default_effort`, `vision`, `context_length`, `max_output`, optional `reasoning_passback`, optional `verbosity` (low, medium, high, xhigh or max, sent as OpenRouter's verbosity parameter; the GPT-6 models use low, which makes their answers shorter), optional `note` and optional `fallback` (another model id), optional `claude_code` (the Claude Code model id, for example `claude-sonnet-5-5`; a model that has it runs in Claude Code while Claude models is set to Claude plan), optional `tiers` (`fast`, `ultrafast` or `flex`, each a list of routes that replaces `provider_order` for that tier, or an object with `provider_order`, an optional `id` when the tier is another OpenRouter model and an optional `max_output` when the tier's endpoint allows fewer output tokens) and optional `default_context` (`limit`, null for the full window, and `compact_percent` from 50 to 95), which applies until the user sets that model's Context limit or Auto-compact. `provider_order` lists OpenRouter provider slugs or exact endpoints (for example `relace/fp4`) that OpenRouter tries one after another; no other provider is used. DeepSeek V4.1 Flash goes to DeepSeek first and to Relace's fp4 endpoint when DeepSeek fails. With several routes the strictest documented image and request size limit among them applies, so DeepSeek V4.1 Flash requests stay under Relace's 8 MiB even when DeepSeek answers.
- `side`: fixed models for side jobs: `title`, `overseer`, `vision`, `reasoning_status`, `transcription` (dictation), `git_text` (commit messages and pull request text in the Files panel).
- `plan_side`: the side models used with GPT models set to ChatGPT plan, a `model` and an `effort` for `title`, `overseer`, `vision` and `git_text` (all GPT 6 Luna, at effort medium for `overseer` and low for the others). When the signed-in account does not list that model, the first model the account offers is used (for `vision` the first with image input) at its lowest effort. Dictation keeps `side.transcription` and the live status line keeps `side.reasoning_status` through OpenRouter.
- `side_models`: the context window (`context_length`, `max_output`) of side models that are not agent models. The diff for `git_text` is sized to that model's window minus its output.
- `image_models`: models for generate_image, each with `id`, `label` and `quality`.

Model calls take one of three routes, set by the two billing switches in Settings > General. With API pricing on both every model call goes through OpenRouter with the key from Settings > General. With GPT models set to ChatGPT plan every call for an OpenAI model the signed-in ChatGPT account offers goes to OpenAI's Responses API with that account and counts against the plan, and the side jobs use the plan's side models there. With Claude models set to Claude plan every main turn, sub-agent run and compaction on a Claude model runs in Claude Code with the user's Claude subscription. Everything else (models of other vendors, OpenAI models the account does not offer, Claude models while the Claude plan is off, image generation, dictation) goes through OpenRouter with the stored key.

When a model call hits a rate limit (HTTP 429), a provider outage, an interrupted stream, a timeout or a broken empty answer (no text and no tool call, with the provider's finish reason MALFORMED_RESPONSE, MALFORMED_FUNCTION_CALL or UNEXPECTED_TOOL_CALL, or OpenRouter's finish reason error; Gemini models send these now and then), the app retries it after 2, 5, 10, 20, 30, 60, 120 and 120 s, at most 9 attempts and never longer than 10 minutes after the first attempt; a Retry-After from the server is followed up to 120 s. The answer shows "Answer interrupted, attempt n/total" ("Antwort unterbrochen, Versuch n/total") meanwhile. A model with a fallback route switches to it after 3 failed attempts. Compaction calls use their own retry plan (see context.md). When OpenRouter answers 402 with the number of output tokens the balance or key limit can still afford (it checks this even for requests that run on the user's own provider key), the app sends the round again with that number, and again with each smaller number OpenRouter names; below 64,000 affordable tokens it stops and shows the credits error. A turn that ends with an error shows one card in the same neutral look as the command cards: an amber alert icon, the error in plain words in the interface language and "Details" at its right end, which unfolds the provider's raw message.

On the ChatGPT plan rate limits, outages and timeouts retry the same way. Four plan errors end the turn without a retry and never fall back to OpenRouter: "The ChatGPT sign-in is missing or has expired." ("Die ChatGPT-Anmeldung fehlt oder ist abgelaufen.") with "Open settings" ("Einstellungen öffnen"); "ChatGPT plan usage limit reached. Review your plan or this app's limit in ChatGPT settings." ("Das Nutzungslimit deines ChatGPT-Abos ist erreicht. ...") with the account's email and "Manage usage" ("Nutzung verwalten"), without a reset time because OpenAI does not give one; "This ChatGPT account or workspace cannot use plan usage in this app." ("Dieses ChatGPT-Konto oder dieser Workspace kann die Abo-Nutzung in dieser App nicht verwenden."); and "This model is not available on your ChatGPT plan." ("Dieses Modell ist in deinem ChatGPT-Abo nicht verfügbar."), after which the app loads the account's model list again; once that list no longer names the model, the model runs through OpenRouter.

On the Claude plan Claude Code retries rate limits and outages itself, and the answer shows "Answer interrupted, attempt n/total" meanwhile; VantheaX adds no retry of its own. Five Claude plan errors end the turn and never fall back to OpenRouter: "The Claude Code login is missing or cannot be used for the Claude plan." ("Die Claude-Code-Anmeldung fehlt oder kann für das Claude-Abo nicht verwendet werden.") with "Open settings" ("Einstellungen öffnen"), also when Claude Code would bill an API key or run on another API backend (for example Bedrock, Vertex or a gateway) instead of the subscription, after which the login row checks the login again; "Claude plan usage limit reached." ("Das Nutzungslimit deines Claude-Abos ist erreicht."), whose Details carry Claude Code's text with the limit (for example five_hour) and the local reset time when Claude Code gives one; "This Claude account cannot use the plan right now." ("Dieses Claude-Konto kann das Abo gerade nicht nutzen."); "This model is not available on your Claude plan." ("Dieses Modell ist in deinem Claude-Abo nicht verfügbar."); and "Claude Code could not be started or stopped unexpectedly." ("Claude Code konnte nicht gestartet werden oder wurde unerwartet beendet."). Other errors Claude Code reports (an outage after its own retries, a request too large for the context, a bad request) show the usual error cards.

## Built-in skills in the package

The built-in skills, including this one, ship as plain files in `resources\skills` next to VantheaX.exe, outside `app.asar`.

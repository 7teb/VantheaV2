# Composer, messages and file changes

## Composer pickers

The model, the effort and the permission mode are app-wide settings chosen at the composer. They apply to new turns in every chat, including turns started by agent reports and background tasks.

- Model picker ("Select model" / "Modell wählen"): opens on a small effort view. Its top row shows the chosen model and effort with a chevron; clicking it (or Right on it) opens the list of the catalog's agent models under a back row "Model" ("Modell"), and picking a model returns to the effort view for that model. Below the top row an "Effort" ("Aufwand") slider has one stop per effort of the chosen model, Major last: clicking a stop, dragging the knob or Left and Right change the effort at once and the menu stays open; Enter, Escape, Tab or a click outside close it. When the effort goes to Major the slider fill flashes, turns into a purple gradient, sparks run out from under the knob and a soft sheen sweeps over it every few seconds. A model with only one effort opens the menu on the list and closes it on pick. Every chat keeps its own model, effort and Pro setting: switching chats switches the picker to that chat's choice, and a change in the picker applies to the open chat only. A chat from before this existed shows the model and effort of its last answer until it is changed. A new chat starts with the model and effort picked last, with Pro off. When a turn runs on another model than the chat's last answer, it starts with a note to the model, not shown in the chat, that names the previous model and the new one and says that the earlier answers are not its own. The note is part of that turn's first request only, never added in the middle of a turn, and later turns replay it at the same place.
- "/" command Pro ("Pro"): listed only while the chosen model is a GPT 6 model; for every other model it does not appear. It switches the open chat (or the new chat about to be started) to the Pro version of its GPT model, the same model served with OpenRouter's Pro reasoning mode under its own slug (openai/gpt-6.1-sol becomes openai/gpt-6.1-sol-pro). It is not a separate entry in the picker: the picker label changes, for example "GPT 6.1 Sol" to "GPT 6.1 Sol Pro", and running /pro again switches back. The setting stays with the chat, also across restarts and when the chat switches to another model and back. Sub-agents deployed without a model of their own run on the same model as the main agent, so on Pro as well.
- "/" commands Fast ("Fast"), Ultrafast ("Ultrafast") and Flex ("Flex"): listed only when the chosen model has that endpoint on OpenRouter: Fast for GPT 6.1 Sol, GPT 6.1 Terra, GPT 6 Luna, GPT 6 Astra and DeepSeek V4.1 Flash (about twice the price per token), GLM 5.3 and MiMo V2.6 Pro (Xiaomi's Ultraspeed model, about ten times the price), Ultrafast for GPT 6.1 Sol and GPT 6 Astra (about six times), Flex for GPT 6.1 Sol, GPT 6.1 Terra, GPT 6 Astra, Gemini 4 Argon and Gemini 4 Carbon (half the price, slower). Fast and Ultrafast route the request only to the openai/fast or openai/ultrafast endpoint, for DeepSeek V4.1 Flash only to Baseten's fast endpoint (baseten/fast, at most 262,144 output tokens per answer instead of 393,216), for GLM 5.3 to z-ai/glm-5.3:nitro on baseten/fast first and to its normal providers when Baseten is unavailable, and for MiMo V2.6 Pro to xiaomi/mimo-v2.6-pro-ultraspeed on Xiaomi, without falling back to the normal one; Flex sends it to the provider's Flex tier first and to the standard route when Flex is busy. The model picker has no separate Flex entries. The three combine with Pro, exclude each other, and stay with the chat like Pro; a new chat starts with all off. The picker label shows it, for example "GPT 6.1 Sol Pro Fast" or "GPT 6 Astra Flex". A chat that used one of the former Flex entries opens with that model and Flex on, and a chat, setting or scheduled task on the former GLM 5.3 Fast entry opens as GLM 5.3 with Fast on. Sub-agents run on the normal endpoint of their model, also when the main agent runs on Fast, Ultrafast or Flex; deploy_agent gets the Flex variant only by naming its `:floor` id, which list_models lists.
- Mode picker ("Command permission" / "Befehlsfreigabe"): Ask (Fragen), Auto (Auto), Full auto (Voll-Auto).
- "Plan" chip: shows in the composer bar only while plan mode is on, highlighted like the other chips; hovering turns its icon into an x and a click switches plan mode off. The + menu switch "Plan mode" and the "/" command Plan mode change the same setting. The agent may only read and inspect, then presents its plan with present_plan; accepting the plan starts a turn that implements it.

## Composer menus

The + button at the bottom left ("Add files and more" / "Dateien und mehr hinzufügen") opens a menu above the composer.
- The section "Add" ("Hinzufügen") holds four rows. "Files" ("Dateien") opens the file picker. "Work in a project" ("In einem Projekt arbeiten") opens the project choice: it picks a project folder and starts a new chat there, text typed in a new chat moves along, and its hint shows the current project or "No project" ("Kein Projekt"). "Plan mode" ("Planmodus") is a switch. "Worktree" is a switch that only works on the new-chat screen of a project (see Worktrees in worktrees.md): its hint shows where the worktree starts, "From main" ("Von main") with the branch the project folder is on or "From the current commit" ("Vom aktuellen Commit") on a detached HEAD, plus "Submodules stay empty" ("Submodule bleiben leer") when the repository has submodules. While the menu opens it checks the project, and the row is disabled with the reason: "Only when starting a chat" ("Nur beim Start eines Chats") in an existing chat (the switch shows whether that chat works in a worktree), "Needs a project" ("Braucht ein Projekt"), "Not a Git repository" ("Kein Git-Repository"), "Needs a first commit" ("Braucht einen ersten Commit"), "Folder is not in the last commit" ("Ordner ist nicht im letzten Commit") or "Git is not installed" ("Git ist nicht installiert").
- While Worktree is on, a "Worktree" chip with a folder-branch icon shows in the composer bar after the Plan chip. Its tooltip says "New branch and folder for this chat, from main" ("Neuer Branch und Ordner für diesen Chat, von main"), plus "Submodules stay empty" when that applies; hovering turns the icon into an x and a click switches Worktree off. Sending the first message (or running Initialize, Create GitHub repository or Review) then creates the worktree and the chat; that can take a few seconds on a large repository, and a failure keeps the text in the composer with the error. The switch goes back to off for the next new chat.
- Below that are the tabs "Skills" and "MCP". Skills lists the enabled skills that load without error, with their descriptions; MCP lists every configured server with its state. Clicking a skill or a ready MCP server adds a chip to the message, and clicking it again removes it. Servers that are not ready are shown disabled with their state. "Manage skills" ("Skills verwalten") and "Manage MCP servers" ("MCP-Server verwalten") open the settings.
- A chip shows in the composer bar after the mode picker (and after the Plan chip while plan mode is on), highlighted like the Plan chip; hovering it turns its icon into an x, and a click removes it. When the message is sent, each chip becomes an instruction at the top of the message: Use the skill "<name>" for this request: load it with read_skill first and follow it. / Use the tools of the MCP server "<name>" for this request. The Visualize chip from the "/" command becomes: Answer this message with the visualize tool: build an interactive visualization that explains or shows the answer, and keep the text around it short. A message with only chips can be sent.

Typing "/" at the start of the message or after a space opens "Commands" ("Befehle"). The list filters as you type, and the English command names also match in the German interface. Arrow keys move, Enter or Tab runs a command, Esc closes the list until the "/word" is gone, Backspace on an empty filter removes the "/" and closes it, ArrowRight opens a submenu and ArrowLeft or Backspace goes back. Running a command removes the "/word" from the draft. When nothing matches, no list shows and Enter sends the text.
- Compact ("Komprimieren"): compacts now, the same as "Compact now" in the context popup; its hint shows how full the context is.
- Auto-compact ("Auto-Komprimierung"): submenu 50 to 95% for the current model (see context.md).
- Context limit ("Kontextlimit"): submenu with "Model maximum" and presets below the window (see context.md).
- Archive chat / Restore chat ("Chat archivieren" / "Chat wiederherstellen"): archiving the open chat moves to a new chat (see Chat archive in interface.md).
- Pin chat / Unpin chat ("Chat anpinnen" / "Chat lösen").
- Fork chat ("Chat verzweigen"): copies the chat up to its latest message into a new chat and opens it.
- Memories ("Erinnerungen"): a panel above the composer with the saved memories, a delete button per entry and a field to add one (see the Memory settings in settings.md).
- Hooks: opens Settings > Hooks (see hooks.md). It needs no chat.
- Initialize ("Initialisieren"): starts a turn that shows in the chat as your message "/init" and asks the agent to inspect the project and create AGENTS.md, or update it if it exists (see Initialize). In a new chat of a project it first creates the chat, moves the typed text along and starts the request there.
- Create GitHub repository ("GitHub-Repository erstellen", found by typing /gitinit, git or github): starts a turn that shows in the chat as your message "/gitinit". The agent first asks three questions in the question form (the repository name, private or public, and which GitHub users to invite) and creates nothing before you answer. Then it checks the GitHub CLI (gh auth status; without gh or its login it tells you to install it and run gh auth login yourself), stops to ask if a remote named origin already exists, runs git init and makes a first commit with a .gitignore that keeps out build output, dependencies, logs and secrets when the folder is not a repository yet, creates and pushes the repository with gh repo create, invites the named users (each gets a GitHub invitation to accept) and ends with the repository URL. Like Initialize it works in a new chat of a project and counts as your own request for the automatic review.
- Review ("Review", also found by typing pr, pull request, diff or prüfen; hint "Current changes, or /review 123 for a pull request" / "Aktuelle Änderungen, oder /review 123 für einen Pull Request"): starts a turn that shows in the chat as your message "/review" and asks the agent to review the project's current changes, meaning the uncommitted changes and the commits of the current branch against the remote default branch. Typing "/review 42" or "/review #42" as the whole message and pressing Enter reviews pull request #42 instead and shows as "/review 42"; the agent reads it with gh pr view and gh pr diff, and without gh or its login it tells you to install it and run gh auth login. Any other text after /review is sent as a normal message. The agent collects the diff with read-only git or gh commands, deploys one explore sub-agent "Reviewer" with a fixed reviewer brief and the whole diff, waits for its report, checks every finding against the code, drops the ones that do not hold, and reports the verified findings by severity with file, line, trigger and fix, plus how many it dropped. Only when the diff would not fit the reviewer's context window with room for its work (the request names the window and the compaction point of the current model), or would not fit into one response of the main agent, it passes the diff of the files with the most changed lines and names the other files for the reviewer to read from the project. Nothing is edited, staged, committed, pushed, checked out or commented on GitHub. In a new chat the review of current changes always starts in the project folder itself, also when the Worktree switch is on, because a fresh worktree has none of those changes; a pull request review respects the switch. Like Initialize it works in a new chat of a project, uses the current model, effort and permission mode, and counts as your own request for the automatic review. A typed /review that cannot run (turn running, compacting, no project) shows the reason under the composer and keeps the text.
- Plan mode ("Planmodus"): switch.
- Visualize ("Visualisieren", also found by typing chart, diagram, graph, visual or widget): switch; it adds or removes a "Visualize" ("Visualisieren") chip with a pie chart icon in the composer bar, which asks the agent to answer the next message with an inline visualization (see Inline visualizations in turns.md). It needs no chat and no project.

A row that cannot run is disabled and shows the reason. "Needs a chat" ("Braucht einen Chat") applies to Compact, Archive, Pin and Fork. "Needs a project" ("Braucht ein Projekt") applies to Initialize, Create GitHub repository and Review in a chat or new chat without a project. "Turn running" ("Turn läuft") applies to Compact, Fork, Initialize, Create GitHub repository, Review and archiving. "Compacting" ("Wird komprimiert") applies to Compact, Initialize, Create GitHub repository and Review while a compaction runs. "No model selected" ("Kein Modell gewählt") applies to Auto-compact and Context limit. Pin and Unpin are disabled on an archived chat with "Restore the chat first" ("Erst den Chat wiederherstellen").

While the + menu or the command list is open, the task list and the other cards above the composer slide up above it and back when it closes. When the room above the composer is too small, the menu gets shorter and the cards get one shared height limit and scroll on their own, so the stack stays inside the window. The rows of a menu fade in one after another when it opens. The Context usage and Memories panels grow out of the composer when they open and shrink back into it when they close; the task list grows in the same way when it appears in an open chat.

Attached files and images show in the message box as small square chips, an image as its thumbnail and a file as a file icon over its name, with the remove button inside the chip's top right corner. A new chip pops in and a removed one shrinks away; the row of chips grows in with the first chip and shrinks away with the last.

## Dictation

The microphone button left of the send button dictates into the message box. A click asks for the microphone (a spinner while it opens; clicking it then cancels) and starts recording: the button turns into a small pill with a scrolling waveform of the input level and a stop square. Clicking the pill stops and puts the transcript at the cursor of the message box, with a space on each side where words would touch, so it can be edited before sending. Enter or the send button while recording stops, transcribes and sends in one step. Esc cancels the recording without sending anything, as does switching to another chat. While the text is transcribed the button shows a spinner. The audio (WebM/Opus, recorded in the window) goes to OpenRouter's transcription endpoint with the catalog's `side.transcription` model (ElevenLabs Scribe v2, which keeps German and English apart in mixed speech); nothing is saved to disk. A recording shorter than a quarter second is dropped. Errors show under the message box: no microphone access ("Enable microphone access to dictate" / "Erlaube den Mikrofonzugriff, um zu diktieren"), no microphone, the microphone in use by another app, an empty result ("Didn't catch that, please try again"), or the provider error.

## Queued messages

The composer, the message editor and the feedback field of approval and question cards check spelling in German and English and underline misspelled words in red; a right click on one offers suggestions and "Add to dictionary" ("Zum Wörterbuch hinzufügen"). Other fields (settings, search, rename) do not check spelling.

A message sent with Enter (or the send button) while a turn runs does not go to the agent at once: it waits as a row in the tab behind the top edge of the composer, above the composer strip (see Composer strip), and is sent when the turn ends; a new row grows in. "Steer" ("Steuern") on the row hands it to the running turn, which adds it at its next model round. In the chat the steered message then shows inside the running turn, where the turn picked it up, as the same right-aligned bubble as a normal user message, attachments included. Each row has "Steer" ("Steuern") while a turn runs or "Send" ("Senden") when none runs, a trash button ("Discard" / "Verwerfen") and a "..." menu with "Edit message" ("Nachricht bearbeiten"). Edit message takes the message out of the queue and puts its text and attachments back into the composer in front of anything already typed there. A row marked "Waiting for next round" ("Wartet auf nächste Runde") is already handed to the turn and cannot be edited or discarded; a row with a warning icon was not sent and can be steered, sent, edited or discarded again.

## Composer strip

Behind the top edge of the composer sits a tab. Queued messages show at its top (see Queued messages), and below them a strip in small gray text: the branch, the project name and the context ring. The tab is hidden when none of them has anything to show.
- Branch: a worktree chat shows its worktree branch with the worktree folder as tooltip ("Worktree: <path>"); when the worktree is on no branch (a detached HEAD), the first seven characters of its commit show instead, and when the worktree folder is missing the branch turns red with the tooltip "Worktree folder is missing" ("Worktree-Ordner fehlt"). A chat without a worktree shows the current branch of its project when the project is a Git repository. A worktree branch is read again when the chat opens, when a turn ends and when the window gets focus. The branch of a project is read when the project is first shown; while it is the current project, it is read again when a turn of one of its chats ends and when the window gets focus. So a branch switched outside the app shows up.
- Project name: the name as in the sidebar, the full path in the tooltip.
- Context ring: a small ring with the percent of the context window in use, in the accent color and red from 90%, shown once the chat's context has been measured. A click opens or closes the "Context usage" panel (see context.md).

## Answer actions

Under a finished answer sit, from left to right: "Copy answer" ("Antwort kopieren"); "Regenerate answer" ("Antwort neu generieren"), only under the newest answer to a message the user wrote and not while a turn runs, which sends that message again with the chat's current model, effort and mode and replaces the answer, while files the old answer changed stay as they are; "Fork chat from here" ("Chat ab hier verzweigen"); and an info icon whose tooltip names the effort, the time of the whole turn and the context used, for example "Major · 2m 54s · 48k of 1.0M tokens"; it never names the model. The row shows on hover, and always under the newest answer; it fades in when the answer is done. While an answer streams, each new block of it (a paragraph, a list, a table or a code block) fades in. The actions of your own message, "Copy" ("Kopieren"), "Edit" ("Bearbeiten", not for a command such as /init) and "Fork chat from here", show on hover to the left of its bubble; on a touch screen or in a window up to 600 px wide they sit below it.

## File links in answers

A Markdown link in an answer that is not a web address shows as a file name with a file icon in purple, with a dashed underline on hover. Clicking one inside the chat's folder (the folder the Files panel shows) opens that file in the Files panel on the right; a link to a path outside that folder opens Explorer with the file selected. Relative paths count from the chat's folder; absolute Windows paths, `file:///` links and a trailing line number such as `:42` or `#L10` work too.

## File changes and Undo

write_file and replace_in_file change an existing file only after the agent read it with read_file, and only while the file is unchanged on disk since that agent's last read or write of it. Otherwise the call fails without writing and tells the agent to read the file again; nothing is shown to the user. This counts per agent: a file the main agent read is still unread for a sub-agent. When the file changes in between, through another agent, a command, the user or another program, the next edit fails until the agent reads it again. Creating a new file needs no read. The hashes are saved with the chat, so a read still counts after an app restart as long as the file's content is the same; deleting the chat deletes them.

A finished turn that changed files with write_file or replace_in_file ends with a file card listing those files with their +/- line counts. The card appears only when the turn really ends: not while it streams and not while a sub-agent it started still runs; for a turn joined by agent report turns it is one card at the very end for the files of all of them. Clicking a file in the card opens it in the Files panel with its current content. Only the card of the newest assistant turn has an "Undo" ("Rückgängig machen") button, and a joined card only when all its files come from that newest turn; it is disabled while a turn runs. Undo does not restore files itself: it sends a message to the agent that names the files of that turn (marking the ones it created) and asks it to put edited files back, delete created ones, undo changes it made through commands and change nothing else. The message shows in the chat as the chip "Undo requested" ("Rückgängig machen angefordert"), uses the current model, effort and permission mode, and counts as the user's own request for the automatic review. The agent rebuilds earlier content from its own edits or from git, so a file it changed through a command without reading it first may not come back exactly; it is asked to say so. In a Git folder the card lists the files of the turn's snapshot diff instead (see Diff view in the Files panel in interface.md): everything that changed in the chat's folder during the turn, also through commands, sub-agents and background tasks started in it, titled "3 files changed" ("3 Dateien geändert") with "binary" ("binär") for binary files; until that list arrives, and in a folder without Git, it lists the edit-tool files as "3 files edited". A turn that changed files only through commands therefore also gets a card, once its snapshot list has files; a turn without changes gets none. The card head has "Show diff" ("Diff anzeigen") before Undo, also while a turn runs: it opens the Files panel on the Diff view at that turn with the file list. Clicking a deleted file in the card opens its diff there; clicking any other file opens it in the Files panel's Files view (leaving the Diff view). Undo still works from the edit-tool files and is unchanged.

## Initialize

The "/" command Initialize sends the agent a request to inspect the open project and create AGENTS.md in the project root, or update it if it exists: install, build, run and test commands (including a single test), lint and format, the layout, the conventions the code follows, and gotchas, only what it verified, keeping the rules a person wrote and changing no other file. The request shows in the chat as a normal user message "/init" (it can be copied and forked, not edited), while the agent receives the full request text; it uses the current model, effort and permission mode, and counts as the user's own request for the automatic review. In Auto the automatic review decides on writing AGENTS.md, like on every change to AGENTS.md or CLAUDE.md; the /init request counts as the user asking for it.
